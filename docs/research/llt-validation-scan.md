# LLT input validation: one traversal for exactly symmetric rows

The public implementation at `2f23d66af38fe4aed42811cdf6438af73de620c5` combines finite-value, maximum-magnitude and exact-symmetry checks for row-contiguous LLT inputs of size at least 128. The factorization arithmetic, public API and workspace sizes are unchanged. The previous implementation at `4843919` traversed the complete input and then compared both triangles.

The helper reads 2×2 tiles from both triangles. Equal opposite values have the same absolute magnitude, so the maximum can be accumulated from one triangle. Diagonal packets and odd tails receive finite checks. A nonexact comparison falls back to the original complete finite-value traversal and normalized symmetry test. This includes off-diagonal NaNs: they fail equality, and the fallback preserves nonfinite-input precedence over asymmetry. Equal infinities produce a nonfinite maximum. Failed input validation leaves factor storage untouched.

The [COFF dumps and hashes](../validation/performance/large-llt/input-validation/objects/manifest.json) capture the actual compiled helper and the previous public factorization, together with Eigen's generated kernels. Both use MSVC `/O2 /fp:precise`, SSE2 double packets, one thread, CPU 0 on the measured P core. This change addresses repeated input traversal; it does not establish cache-miss or hardware-counter claims.

The measurement controls are diagnostic, three fresh processes with five samples per phase, at least 20 ms per sample. They do not replace the five-process, thirty-sample final acceptance. In the subsequent [single-change controls](../validation/performance/large-llt/input-validation/controls/manifest.json), the current 128-variable factor takes about 44.4–44.7 µs and remains roughly 1.7–2.0% slower than Eigen. Factor plus solve takes about 46.4–46.6 µs, with Eigen ratios 0.987–0.994. Grouping four independent exact packet divisions does not consistently improve this factor, so it was not adopted. The [earlier formal measurements](large-llt-assembly.md) remain explicitly tied to source `4843919`.

Two-variable setup remains unfinished. The original caller harness allocates four initialized buffers; its setup costs approximately 0.151 µs. Separate controls combine factor/workspace storage into an arena and leave completely overwritten buffers uninitialized, using three allocations as Eigen does. Those controls reduce the time but still leave a gap. They are caller-policy experiments, not a change to LLT's allocation-free prepared API. The original measurement is retained.

Permanent tests cover sizes 128 and 129, row, padded row, interleaved and column inputs; NaN padding, signed zero, tolerance boundaries and first mismatch, NaN/±Inf in both triangles/diagonal/odd tails, nonfinite precedence, disabled symmetry checks, and finite scale endpoints through `DBL_MAX`. Existing exact-factor, solve, padding and late-failure tests remain.

All eight local PC configurations—MSVC, GCC 15.3, Clang 20.1.8/libc++, and Clang/libc++ ASan/UBSan, each Debug and Release—pass kibo's numerical, contract, scalar and no-runtime gates. Each retains exactly sixteen existing Eigen accuracy CHECK failures, eight per layout. MSVC Release allocation instrumentation is skipped; that limitation is preserved. See the [local failure audit](../validation/performance/large-llt/input-validation/local/failure-set.json).

[Hosted run 37629654886](https://github.com/takuto-NA/kibo-linalg/actions/runs/37629654886), also source `2f23d66`, finishes with the same Eigen-only failures across its eight PC test runs. WASM Node and Chromium/Firefox/WebKit pass; ESP32-S3 and C3 cross compilation passes. Physical ESP execution remains unavailable. The [hosted audit](../validation/performance/large-llt/input-validation/hosted/evidence.json) retains the exact failure maps and artifact hashes. Neither the CI assertions nor accuracy thresholds were relaxed. Full numerical CI remains red pending the separate Eigen-diagnostic policy decision.
